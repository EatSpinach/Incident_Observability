## 📋 Next Steps to Deploy

### Step 1: Create GitHub Repository

1. **Go to GitHub**
   - Open https://github.com/new in your browser
   - Sign in to your GitHub account (or create one if needed)

2. **Create New Repository**
   - Repository name: `incident-observability` (or your preferred name)
   - Description: `Web application for evaluating incident documentation quality`
   - Visibility: **Public** (required for free Render deployment)
   - **DO NOT** initialize with README, .gitignore, or license (we already have these)
   - Click "Create repository"

3. **Copy the Repository URL**
   - You'll see something like: `https://github.com/YOUR_USERNAME/incident-observability.git`
   - Keep this URL handy

### Step 2: Push Code to GitHub

Open your terminal in the project directory and run:

```bash
# Add GitHub as remote (replace YOUR_USERNAME with your actual GitHub username)
git remote add origin https://github.com/YOUR_USERNAME/incident-observability.git

# Rename branch to main (if needed)
git branch -M main

# Push code to GitHub
git push -u origin main
```

**Expected Output:**
```
Enumerating objects: 19, done.
Counting objects: 100% (19/19), done.
...
To https://github.com/YOUR_USERNAME/incident-observability.git
 * [new branch]      main -> main
```

### Step 3: Sign Up for Render

1. **Go to Render**
   - Open https://render.com in your browser

2. **Sign Up**
   - Click "Get Started" or "Sign Up"
   - Choose "Sign up with GitHub" (recommended)
   - Authorize Render to access your GitHub account
   - Complete the sign-up process

3. **Verify Email**
   - Check your email and verify your account

### Step 4: Deploy Your Application

1. **Create New Web Service**
   - Click the "New +" button in the top right
   - Select "Web Service"

2. **Connect Repository**
   - You'll see a list of your GitHub repositories
   - Find "incident-observability" and click "Connect"
   - If you don't see it, click "Configure account" to grant access

3. **Configure Service Settings**
   Fill in the following:
   
   - **Name**: `incident-observability` (or your preferred name)
     - This will be part of your URL
   
   - **Region**: Choose closest to your location
     - Example: Oregon (US West) or Frankfurt (EU)
   
   - **Branch**: `main`
   
   - **Root Directory**: Leave blank
   
   - **Environment**: `Python 3`
   
   - **Build Command**: 
     ```
     pip install -r requirements.txt
     ```
   
   - **Start Command**:
     ```
     gunicorn app:app
     ```
   
   - **Plan**: Select **"Free"**
     - $0/month
     - 750 hours/month
     - Automatic sleep after 15 min of inactivity

4. **Add Environment Variables**
   - Scroll down to "Environment Variables"
   - Click "Add Environment Variable"
   - Add the following:
     - **Key**: `SECRET_KEY`
     - **Value**: Click "Generate" or use a random string
       - Example: `your-super-secret-random-key-here-change-this`
   
5. **Advanced Settings (Optional)**
   - Auto-Deploy: **Yes** (enabled by default)
     - Your app will automatically redeploy when you push to GitHub
   
   - Health Check Path: `/` (default is fine)

6. **Create Web Service**
   - Review all settings
   - Click "Create Web Service" button at the bottom

### Step 5: Wait for Deployment

1. **Monitor Build Process**
   - You'll see a live log of the deployment
   - This usually takes 2-5 minutes
   - Watch for these stages:
     - ✅ Cloning repository
     - ✅ Installing dependencies
     - ✅ Building application
     - ✅ Starting service

2. **Deployment Complete**
   - When you see "Your service is live 🎉"
   - The status will change to "Live"
   - You'll see your URL at the top

### Step 6: Get Your URL

Your application will be available at:
```
https://incident-observability-XXXX.onrender.com
```

Where `XXXX` is a random string generated by Render.

**Example URLs:**
- `https://incident-observability-abc123.onrender.com`
- `https://incident-observability-xyz789.onrender.com`

### Step 7: Test Your Application

1. **Click the URL** at the top of the Render dashboard
2. **Test the application**:
   - Upload a sample Excel file
   - Click "Evaluate Incidents"
   - Verify results appear correctly
   - Try exporting results

3. **Share the URL**
   - Copy the URL
   - Share with your team
   - Add to documentation
   - Bookmark for easy access

## 🔧 Troubleshooting

### Build Failed
**Check:**
- requirements.txt is correct
- All files are committed
- Python version in runtime.txt is supported

**Solution:**
```bash
# View build logs in Render dashboard
# Fix issues locally, then:
git add .
git commit -m "Fix build issues"
git push origin main
```

### Application Not Starting
**Check:**
- Start command is correct: `gunicorn app:app`
- app.py exists in root directory
- No syntax errors in code

**Solution:**
- View logs in Render dashboard
- Check for error messages
- Fix and redeploy

### 502 Bad Gateway
**Possible causes:**
- Application crashed
- Out of memory
- Startup timeout

**Solution:**
- Check logs for errors
- Verify memory usage
- Consider upgrading plan if needed

### Slow First Load
**This is normal!**
- Free tier apps sleep after 15 min inactivity
- First request wakes up the app (~30 seconds)
- Subsequent requests are fast

**Solutions:**
- Upgrade to paid plan (no sleep)
- Use a service like UptimeRobot to ping your app
- Accept the trade-off for free hosting
